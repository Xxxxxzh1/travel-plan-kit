# Ticket ingest

Tickets arrive in whatever shape the issuer felt like: airline PDFs, rail PDFs
with five pages of terms, Booking.com screenshots, photos of a printed voucher.
`scripts/ingest_tickets.py` normalises all of it into small JPEGs that can be
embedded in the roadbook.

## What it does

| Input | Handling |
|---|---|
| PDF | rasterised per page with `pdftoppm` at 105 dpi |
| PNG / JPEG / WebP / HEIC / TIFF / BMP | downscaled and re-encoded |
| anything else | a clear error naming the file and the supported formats |

Then, per image:

- resize to at most `--width` (default **1050px** — roughly a phone's width at
  3x, which keeps QR codes scannable)
- re-encode as JPEG at `--quality` (default **62**)
- cache by `sha1(path, size, mtime)` so rebuilds are fast and idempotent

Both tools are optional, with graceful degradation:

- **`pdftoppm` is required for PDFs only.** Without it, PDF tickets fail with a
  message naming the install command. `brew install poppler` / `apt install poppler-utils`.
- **Pillow is optional.** Without it, `sips` is used on macOS; without either,
  images are embedded unresized with a warning.

## Why the defaults are what they are

The numbers are not arbitrary. In the trip this tool was extracted from, 29
ticket files went from **7.3 MB → 3.8 MB** at 105 dpi / quality 62, and the
resulting single-file roadbook was **5.4 MB** — small enough to AirDrop and open
instantly, while QR codes stayed scannable off a phone screen.

Dropping to quality 50 started visibly degrading small print on rail tickets.
Going above 1100px gained nothing legible and cost about 30% more size.

## The page-count detail that matters

A five-page rail PDF and a one-page museum ticket are both "one ticket" to the
user, but they are five images and one image to the renderer. `trip.yaml`
declares them accordingly:

```yaml
- {id: milano-spiez, label: 米兰 → 施皮茨,
   files: [tickets/train-milano-spiez-p1.png, tickets/train-milano-spiez-p2.png]}
```

Each page becomes its own slug (`milano-spiez_0`, `milano-spiez_1`) with the
caption `· 第 N 页` appended, and each is a separate gallery item and lightbox
frame. 23 declared tickets produce 27 images in the example.

## Running it standalone

```bash
python3 scripts/ingest_tickets.py path/to/trip.yaml
```

Prints a per-ticket size before/after table. Useful for finding the one
oversized scan before it lands in the roadbook. The cache lands in
`<trip dir>/.cache/tickets/`, which is gitignored.

## A rule to keep

**Never commit real tickets to a repository you intend to publish.** Ticket
images contain names, dates of birth, booking references, and QR codes that are
themselves the credential. This repo's example uses images generated by
`scripts/make_sample_tickets.py`, which are entirely synthetic and carry a
`SAMPLE DATA — NOT A REAL TICKET` stamp.

If you fork this to plan a real trip, keep the generated output out of version
control — the `.gitignore` has a commented-out `trips/` entry ready for that.
